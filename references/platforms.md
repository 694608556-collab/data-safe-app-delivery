# 平台差异与真实设备诊断

## Windows / 桌面

区分安装目录、应用数据、便携数据、归档文件与自动备份。升级或清理安装包不意味着允许删除同目录的数据库。

主进程/渲染进程和文件桥接需核对真实返回类型。布局改动用实际输出或真实界面确认；界面测试等待可观察状态，如可点击和布局完成，避免仅靠固定延时。

源代码构建通过不证明安装器和便携包内容相同。核对实际打包资源、版本及目标架构。

## Android 文件选择

首先核对操作入口及系统选择器收到的文件类型：完整备份恢复、表格导入、角色导入和目录授权可能完全不同。同一目录在不同入口显示不同文件，可能是预期筛选。

再检查扩展名、系统报告的 MIME 类型、文档提供者、是否只是云端占位、是否可读取流以及授权是否仍有效。跨机型使用系统文档选择器与内容 URI；不要假设固定物理路径或轻易请求全盘访问权限。

正确入口仍隐藏有效文件时，以真实提供者证据调整类型匹配，并在读取后完整校验格式。不要把备份筛选无条件改成接受Excel，或通过删校验消除报错。

## Android 安装与更新

获取准确系统版本、失败原文、来源文件和是否已有安装。区分：安装来源权限、安全检测、文件缺损/错误后缀、签名冲突、系统API或CPU不匹配、分包缺失。

核对实际APK的包名、版本、最低API、原生ABI、签名与现有应用身份。修改minSdk数值不是兼容性证明；WebView能力也须验证。不能按品牌或“鸿蒙”名称推断整个平台不支持，具体系统代际需查当前一手资料。

在错误尚不明确时，不盲目重签、改包名、卸载、清空数据或建议关闭全部安全防护。若目的为保留数据的升级，应核对兼容的覆盖安装路径。用户明确要求真正卸载且知悉数据后果时，按当前授权执行，不用旧偏好否决新指令。

## iOS

明确Windows能执行的共享检查与需要macOS/Xcode的构建/原生/系统UI检查。云端构建可完成对应检查；模拟器的机型名称不使它成为真实iPhone证据。

设备IPA与模拟器二进制不是同一产物：检查实际可执行文件平台、架构、版本、资源，以及是否已签名/需要用户签名。不要自动获取或上传签名材料。

文件选择器、目录授权、分享和生命周期按系统实现验证；外部目录暂缓等产品决定需要保留。Swift与底层C/JS对Unicode、重复键和数值的语义需要差分核对。

## PDF与其他导出

不要只判断文件存在或“能打开”。根据格式核对页数、正文、字体、分页、换行、图片或像素与原文要求。支持合法的新输入分支时保留原校验：例如处理RGBA图像，先验证格式与不透明条件，再验证无损转换，不能删掉像素检查。

打开、分享或导出属于异步操作时，过期请求不得发布旧结果；关闭/切换后核对当前租约或任务身份。

## 宣传和视觉产物（仅任务包含时）

宣传视频、截图和动效不是普通维护任务的必做项。用户要求时，核对实际输出的画面、声音、时长、清晰度/码率和素材授权；配置中写了参数不等于最终文件满足参数。不要把宣传样片当作产品实测证明。
