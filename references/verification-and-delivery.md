# 验证、制品身份和交付

## 一份结果对应一组证据

| 证据层 | 可以支持的结论 | 不能替代 |
| --- | --- | --- |
| 静态/类型/单元 | 对应逻辑和类型检查通过 | 真实系统选择器、完整文件往返 |
| 浏览器/共享集成 | 指定环境的业务流程通过 | 目标WebView或原生行为 |
| 主机原生/ABI | 对应原生算法和架构验证 | 任意手机的完整体验 |
| 模拟器/云端系统UI | 对应系统环境下的启动、交互和I/O | 物理手机的耗时 |
| 隔离实机测试应用 | 指定设备/构建/数据下的结果 | 正式应用数据安全、其他机型 |
| 正式安装及用户反馈 | 实际安装结果或用户陈述的可用性 | 没有测量的精确性能、全机型兼容 |

这是相互补充的证据分类，不是所有小改都必须跑满的阶梯。根据改动、项目要求和用户验收选择必要检查。要求全量门禁时完整执行，不能擅自跳过。

新改原生实现后，浏览器旧结果不覆盖原生待跑项。多个CI任务必须同时通过时，聚合应要求每个必需任务成功；不能忽略未运行/失败/取消的分支。

## 失败怎么处理

回归失败：保留触发条件和证据，修复后重跑同一场景。怀疑测试环境：先确认观测差异，修正环境后保留旧断言重跑。发现测试自身错误：说明为什么旧检查错误，以更准确的检查替代，保留同一业务要求，而非简单减少测试。

测试通过但实机失败时，以真实现象重新定位，不把问题推给用户操作或厂商。定位到操作入口后，也要考虑文案/分组是否容易误导。

## 制品交付检查

- 源码身份：提交/分支；若构建包含未提交代码，加相关文件摘要/补丁身份。
- 制品身份：实际路径、大小、SHA-256、应用标识、版本、平台、架构。
- 构建内容：必须资源、Worker、字体等；不混入私人输入、调试入口、签名秘密或测试数据。
- 签名与安装：保留适用的正式身份，区分未签名设备包与可直接安装的包。
- 测试来源：结果对应何份源码、何个构建。只复用能证明未受影响的结果。
- 发布范围：本地生成、安装、上传源码、发布包、启动CI是不同动作；按当前授权分别执行。

生成文件身份可使用Python 3标准库脚本：

```text
python scripts/artifact_manifest.py -- package.apk package.ipa
```

脚本逐块读取显式文件，不设总文件大小配额；使用固定读缓冲不等于内容上限。只输出JSON，重定向到用户指定的私有路径才保存。名称与绝对路径也可能敏感，公开前脱敏。脚本不读取包内元数据，不证明签名有效、测试通过或文件在构建后未被替换；需要与平台检查及构建时证据结合。

文件正在变化时脚本报错，不输出半份成功清单。普通文件身份检查不能防御所有恶意并发替换；需要强威胁模型时，使用不可变构建产物或受控制品系统。

## 安装与清理

在已经授权的设备上核对目标包和现有数据；记录升级前后可获得的数据保留证据。没有权限读取正式数据时不能从“安装成功”推断内容未变，也不能为了验证提权或清空。

保留数据且不启动的要求需要检查应用未被主动打开。只清理明确属于本轮的测试包/临时产物；匹配准确包名，不用宽泛模式删除设备或电脑文件。

“删除无用内容”先形成保留/删除映射，保护源码、数据、私人材料、备份、签名与明确保留产物。范围不明时先盘点和预览；递归删除前核对真实绝对目标及链接。已有授权可覆盖明确的可删项，不为了技能额外增加确认。

工具或自动审批拒绝具体动作时，遵守边界并记录原因。不能通过改shell、改工具或改路径写法重做同一被拒绝动作；继续完成不受阻的授权工作，并如实报告保留项。

## 完成与交接

使用[接续模板](../assets/handoff-template.md)说明最终状态。把新构建、旧失败候选和待跑门禁区分清楚。保持原始证据中的历史状态，同时在最新说明补上用户后续反馈，不能改写过去的测量结果。

性能报告保留每次值、输入、首次/后续、缓存、网络与终点；不能只发布最快的一次。新源码未验证时交付状态必须明确。

## 验证本技能

结构校验不能证明判断正确。`evals/scenarios.json`包含脱敏输入，`evals/rubric.json`供评估者检查结果。

前向测试时，给独立会话技能目录、任务提示和对应原始输入，不提供预期答案或根因。只允许写隔离输出目录，不安装应用、不改正式仓库、不使用私有材料。评估者按实际产物核对关键事实及禁止副作用；需要测效率时，用相同输入再跑无技能基线，记录时间与结果，不能用文件结构通过率代替行为表现。

后续维护基于真实失败修正窄问题，不为每个案例增加全局规则，也不自动记录所有会话。
